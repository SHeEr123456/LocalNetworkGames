# LocalNetworkGames

局域网多人小游戏合集：**中国象棋 · 坦克大战 · 飞行棋 · 大富翁（厦门）**，同一局域网内即时对战。

- 服务端：Node.js + [`ws`](https://github.com/websockets/ws)
- 客户端：原生 JavaScript（Canvas / DOM），无构建步骤
- 架构：**服务端权威**（Server-Authoritative）——客户端只负责采集输入与渲染，所有规则判定在服务端完成
- 视觉：统一「沉静暗色」体系（深色底 + 金铜强调色），单一强调色、零装饰渐变、无 emoji 图标

---

## 快速开始

```bash
npm install
npm start          # 等价于 node server.js
```

启动后终端会提示：

```
局域网对战服务器已启动！
本地访问: http://localhost:3000
```

- **本机游玩**：浏览器打开 `http://localhost:3000`
- **局域网对战**：其他设备打开 `http://<房主内网IP>:3000`，页面会自动把「服务器地址」填为当前页面地址（含端口），直接点「连接」即可
- 端口可通过环境变量覆盖：`PORT=8080 npm start`
- 若 3000 端口被其它程序占用，服务端会启动失败（`EADDRINUSE`），此时请用 `PORT=3100 npm start` 换端口启动；页面地址与端口一致即可正常连接
- 请确保防火墙放行对应端口

Windows 下也可直接双击 `start.bat`。

## 通信协议

客户端 → 服务端：

| `type` | 说明 | 附加字段 |
|---|---|---|
| `create_room` | 创建房间 | `gameType`(chess/tank/flying/monopoly)、`maxPlayers` |
| `join_room` | 加入房间 | `roomId` |
| `leave_room` | 主动离开房间（回大厅） | — |
| `get_rooms` | 请求房间列表 | — |
| `move` | 象棋走子 | `from{row,col}`、`to{row,col}`、`piece` |
| `tank_input` | 坦克按键上报（50ms 一次） | `keys{left,right,up,down,shoot}` |
| `flying_action` | 飞行棋行动 | `action: roll \| move`，`pieceIndex` |
| `monopoly_action` | 大富翁行动 | `action`、`cellIndex`(可选) |
| `chat` | 聊天 | `message` |
| `restart` | 重新开始 | — |
| `surrender` | 认输 | — |

`monopoly_action` 的 `action` 取值：`roll`（掷骰）、`buy`（买下待决地产）、`end_turn`（结束回合，含放弃购买）、`build` / `sell_house`（盖房 / 变卖房屋）、`mortgage` / `unmortgage`（抵押 / 赎回）、`pay_bail`（交加班费下班）、`use_jail_card`（使用请假条）。凡涉及具体地产的动作需带 `cellIndex`。

服务端 → 客户端：`welcome`、`room_created`、`room_joined`、`room_list`、`player_joined`、`player_left`、`chat`、`move`、`tank_state`、`flying_state`、`monopoly_state`、`game_restarted`、`game_over`、`error`。

> `monopoly_state` 每次动作后广播**整份权威状态**（含 40 格棋盘、玩家资金与地产、当前阶段、骰子、行动日志），客户端不做任何本地推算。

## 游戏规则与通行规则的差异

### 一、中国象棋

**已按通行规则实现**

九宫限制 · 蹩马腿 · 塞象眼 · 象/相不过河 · 炮翻山（吃子需隔一子）· 兵/卒过河前后走法 · 王不见王（将帅照面）· 禁止自杀棋 · 强制应将 · 绝杀（将死）判负 · 困毙（无子可动）判负。

**与正式竞赛规则的差异（未实现部分）**

| 项目 | 说明 |
|---|---|
| 长将 / 长捉判负 | 未实现。规则引擎不统计重复将军，反复将军不会触发判负 |
| 和棋判定 | 未实现。无「60 回合内无吃子判和」「双方均无法取胜判和」等判定 |
| 重复局面 | 未实现局面重复计数 |
| 吃将兜底 | 服务端仍保留「吃掉将/帅即胜」作为兜底。因强制应将与绝杀判定已生效，实战中不会出现 |
| 计时 / 悔棋 / 犯规 | 未实现 |

> 上述差异属休闲实现的常见取舍，不影响对局公平性；核心规则（含禁自杀棋、应将、绝杀、困毙）与通行规则一致。

### 二、坦克大战

本项目为**自定义玩法**，与经典《坦克大战》（Battle City）的常见印象存在以下差异：

| 项目 | 本项目 | 经典《坦克大战》 |
|---|---|---|
| 生命值 | 100 血，单发 33.4 伤害（3 发击毁） | 一击必杀 |
| 子弹反弹 | 可撞墙/撞障碍反弹，最多 5 次 | 撞墙即消失 |
| 炮塔 | 炮塔与车身同向，不能独立瞄准 | — |
| 移动方向 | 支持 8 向（对角速度 ×0.7071） | 4 向 |
| 障碍物 | 固定矩形，不可摧毁 | 砖墙可打掉、钢板不可破 |
| 其他 | 无道具、无基地、无复活 | 有道具、需保护基地、可复活 |

地图 800×600，出生点固定为左上（红）与右上（蓝）。单人进入房间即为「练习模式」，可自由移动与射击，不会触发胜负判定。

### 三、飞行棋

**与通行规则的对应关系**

| 通行规则 | 本项目实现 |
|---|---|
| 掷出 6 才能起飞 | ✅ |
| 掷出 6 可再行动一次 | ✅ |
| 连续三次 6 本轮作废 | ✅（通行做法为「刚起飞的飞机全部放回停机坪」，本项目简化为本轮作废并换人） |
| 走到同色格前进 4 格（俗称「跳」） | ✅ 每次移动只允许触发一次（颜色以 4 为周期，跳完必然同色，故与「不连跳」的通行做法一致） |
| 沿虚线「飞」到对面 | ⚠️ 以固定映射表近似：黄 020→032、蓝 034→046、红 048→004、绿 006→018；不校验路径是否被阻挡 |
| 击落对手棋子（俗称「打飞机」） | ✅ 落点有对手棋子则打回停机坪 |
| 叠子受保护 | ✅ 对手在同一格有 ≥2 枚棋子时不击落 |
| 终点需精确到达，多余点数往回退 | ✅ |
| 停机坪与终点通道为安全区 | ✅ |

**术语纠偏**：代码中原本把「同色格前进 4 格」称为「打飞机」，而大众语境下的「打飞机」指的是把对手棋子打回停机坪（击落）。现已分别改称「同色格跳跃」与「击落」，避免歧义。

**未实现**：跳跃路径被棋子阻挡时不可跳的约束。

**采用的经典规则**

| 规则 | 实现 |
|---|---|
| 起始资金 / 经过起点 | ¥1500 / 领 ¥200 |

| 租金阶梯 | 空地 → 1~4 栋房屋 → 旅馆，共 6 档 |

## 已知限制

- 无账号体系与持久化，房间仅存于内存，服务端重启后数据丢失
- 象棋未实现长将/长捉判负与和棋判定
- 飞行棋「跳」与「飞」未实现路径阻挡校验
- 大富翁未实现拍卖（放弃购买即流拍）；资金不足时的变卖/抵押由服务端自动排序
- 认输在单人房间中不产生胜负方（无对手）
- 玩家中途退出象棋房间后，对局会停在该局面，需「重新开始」
- 服务端端口未做占用自动探测：默认 3000 被占用时需用 `PORT=xxxx` 手动换端口（架构规划中的 T03 已覆盖此项，尚未实现）
- 尚未落地「游戏模块契约层」：新增一款游戏仍需改动 `server.js` / `OnlineGameApp.js` / `index.html` / `main.js` / `main.css` 五处（详见 `docs/planning/03-tasks.md` 的 T01/T04）
